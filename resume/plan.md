# 四周实施方案（含复杂度控制与失败点规避）

> 本项目实际按此计划执行完成。写下这份计划的目的：一是让后续扩展（跨站点全面板、回答端数据）有据可依；二是记录每个阶段「刻意不做什么」——单人项目的失败大多不是因为做得太少，而是因为没守住范围。

## 阶段划分（每周 15–20 小时）

### Week 1 — 问题定义 + 数据管线（~16h）
| 产出 | 工时 |
|---|---|
| 研究问题与两条可证伪假设（H1 剂量-反应 / H2 新兴领域韧性）**书面固定下来**，防止事后挑数据 | 3h |
| 识别设计评审：处理变量怎么定、对照组是谁、最小样本量 | 2h |
| 采集脚本：配额感知 + 断点续传 + 全量缓存（`src/collect.py`） | 6h |
| Pilot：5 个 tag × 3 季度，验证 API 行为、`total` 字段、限速 | 3h |
| **风险核查**：实测 CAISO/SEDE 等备选数据源连通性（本次实测排除了电力方向） | 2h |

**阶段闸门（gate）**：若 pilot 显示无法在配额内拿到核心面板 → 立即降级为半年粒度或砍 tag 数，不恋战。

### Week 2 — 完整采集 + 面板构建 + 基准估计（~18h）
| 产出 | 工时 |
|---|---|
| 完整 tag 面板采集（264 请求，含各领域累计语料存量） | 1h（等限速）+ 监控 |
| 面板构建：去重、时间对齐、处理强度标准化 | 4h |
| 站点全量验证（排除删帖/重打标签假象） | 2h |
| 基准 TWFE + 事件研究第一版 | 6h |
| **第一次诚实性检查**：伪处理时间安慰剂 | 3h |

**阶段闸门**：本次执行中这个闸门真的触发了——安慰剂未通过（p=1e-18）。正确动作不是掩盖，是诊断：预趋势来自技术采用曲线，解法是领域特定趋势。这一步比任何回归都值钱。

### Week 3 — 稳健性与机制（~17h）
| 产出 | 工时 |
|---|---|
| 规格族：TWFE × {无/线性/二次趋势} × {全样本/MATURE} | 5h |
| PPML（计数因变量正确规格） | 2h |
| Wild cluster bootstrap（cluster 仅 6–11 个，渐近 SE 不可靠） | 4h |
| 跨站点 DiD 与归因分解 | 4h |
| 机制讨论：门槛 vs 梯度 | 2h |

### Week 4 — 报告 + 看板 + 简历（~15h）
| 产出 | 工时 |
|---|---|
| 5 张论文级图表 | 5h |
| 分析报告（含局限性，不隐藏零结果） | 4h |
| 交互式看板 | 3h |
| 简历描述中英文 + 面试口径 | 2h |
| README / Makefile / 数据字典 | 1h |

## 4 个可量化评价指标

1. **AI 可归因的峰值 DiD = −51.7 pp**（2022Q3→2023Q4，vs Mathematics 对照），即同期总降幅的 **93.0%**；
2. **归因份额的时间轨迹 = 93.0% → 10.2%**（2023Q4 → 2026Q3，百分点口径）；对数口径下相对差距同期从 53.8% 扩大到 91.2%——两者并列呈现，说明份额收敛是地板效应而非 AI 影响消退；
3. **门槛检验：成熟领域组内斜率 +0.36 pp/log point，p=0.955**（无梯度），叠加伪处理安慰剂 p=0.84–0.99（识别干净）；
4. **复现性：264 个 API 请求 100% 缓存命中，全管线一条命令重跑，原始响应逐字节可追溯。**

## 复杂度控制与失败点规避

| 常见失败点 | 本项目的规避动作 |
|---|---|
| **数据配额陷阱**：第三天发现 API 配额跑不完面板 | 采集器天生配额感知（`quota_remaining` 触底即停）、断点续传、请求级缓存；pilot 先行实测真实配额消耗 |
| **把描述当因果**：画一条下降曲线就宣布「AI 干的」 | 假设在观测数据前书面固定；对照组（数学站点）在采集前就选定，理由（形式证明不可替代）写在报告里而非结果出来后 |
| **平行趋势违反而不自知** | 伪处理时间安慰剂作为 Week 2 的强制闸门，先于任何主结果 |
| **小 cluster 推断失效**（11 个 tag） | 不依赖渐近聚类 SE，wild cluster bootstrap (B=2000) 复核 |
| **范围蔓延**：想给全部问题做 NLP 分类、想爬回答数据 | 范围冻结写在计划里：11 tags × 23 季度。扩展项（回答端、全站点面板、中文社区）记录为 future work 而非顺手做 |
| **追求模型花哨**（深度学习、LLM 嵌入） | 本题的瓶颈是识别而非预测能力，全部估计用 OLS/GLM 完成——方法服务于问题，不是反过来 |
| **只报告显著结果** | 被否定的 H1 作为核心发现之一写入报告标题级结论；这正是本项目最有面试价值的部分 |
