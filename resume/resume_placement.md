# 简历放置与包装指南

## 一、放在哪：取决于你投什么

| 你的目标 | 放在哪个 section | 相对位置 | 命名 |
|---|---|---|---|
| **数据分析 / 数据科学 / 商业分析岗**（默认推荐） | **项目经历** | 实习经历之后、教育经历之前；若无实习，紧随教育经历 | 「独立研究项目」 |
| **申博 / 研究岗 / 学术助理** | **科研经历** | 紧随教育经历，优先于实习 | 「工作论文 / Independent Research」 |
| **产品 / 策略 / 平台治理岗** | **项目经历** | 同左 | 「独立研究项目」 |
| **咨询** | **项目经历**（可并列 1–2 个案例） | 同左 | 「独立分析项目」 |

### 关键判断
- ❌ **不要放「校园经历 / 其他」**——会立刻被归为课外活动，价值归零。
- ❌ **不要放「技能」栏里当一行带过**——这是你目前最厚实的资产，一行浪费了。
- ✅ **求职向放「项目经历」而非「科研经历」**：HR 看到"科研经历"下只有一个无导师、无基金、无发表的个人项目，第一反应是"课程作业"。放"项目经历"+ 可点击的仓库和在线看板，就变成了可验证的产出。

### 页面预算
- 若这是你**唯一**的项目：给足 4 条要点，占约 1/4 页。
- 若你有 2–3 个项目：本项目排第一，其他各 2–3 条。
- **项目数不要超过 4 个**——超过会让每个都显得单薄，不如集中弹药。

## 二、推荐模板（求职向 · 主力版本）

```
生成式AI与知识公共品的供给塌陷：基于Stack Exchange网络的准自然实验      2026.09–2026.10
独立研究项目 · Python | Pandas | Statsmodels | 因果推断 | REST API 数据工程
github.com/gongsjie3-cyber/ai-knowledge-commons · 在线看板: gongsjie3-cyber.github.io/ai-knowledge-commons

· 研究问题：ChatGPT 发布（2022-11-30）是否为在线知识社区的提问量崩塌的
  因果驱动，而非社区自身长期衰退的延续。
· 识别设计：以 Mathematics 站点为对照组（形式证明领域，LLM 难以替代），
  构造跨站点与站内知识领域的双向固定效应 DiD，并以各领域截至 2022 年的
  历史累计问答存量作为「进入 LLM 训练语料的充分程度」的连续处理变量。
· 核心结论：LLM 直接替代解释了冲击后第一年 Stack Overflow 降幅的 93%
  （DiD = −51.7 个百分点）；其后绝对水平的进一步崩塌由跨领域普遍性
  衰亡主导，但相对命运的差距并未收窄（对数口径下从 53.8% 扩大到 91.2%）。
· 方法诚实性：先验假设「语料覆盖越充分、替代越强」被数据否定
  （β ≈ 0，p = 0.96），证据转而支持门槛效应；伪处理时间安慰剂
  未通过，已诊断并修正（引入领域特定趋势后全部通过）。
· 工程交付：配额感知、断点续传的 API 采集器，264 次请求全量缓存；
  `make all` 一条命令复现全部结果、9 张图表与交互式看板。
```

**排版要点**
- 项目名 + 时间（右对齐）；第二行是技术栈，`|` 分隔；第三行是链接
- 要点用 `·`，每条不超过 2 行
- 第一行要点必须是**问题**，不是工具 —— 这是区分"水"和"实"的第一道分水岭

## 三、水 vs 实：四个可自检的分水岭

| 维度 | 水的写法 | 实的写法（本项目） |
|---|---|---|
| **问题** | "对某数据集进行分析" | "ChatGPT 是否为提问量崩塌的因果驱动" —— 有对立的假说可供证伪 |
| **方法** | "使用 sklearn 建模" | "为何选此对照组（理论依据）、如何处理预趋势违反、为何用 PPML 而非 OLS" |
| **结果** | "模型准确率 95%" | "归因份额 93%→10%，且双口径分歧本身是发现" |
| **边界** | 无 | 主动列出：地板效应、小 cluster、API 不含删帖、对照非完美外生 |

**自检提问**：一个做过真实数据分析的人，看完你的描述，会不会问"那你当时为什么选这个方案而不是另一个？" —— 如果会，说明你没写决策依据；如果描述里已经回答了，就不水。

## 四、分岗位换弹药（同一项目，三种讲法）

### A. 数据分析师 / 商业分析
> **口径**：业务问题 → 指标 → 结论 → 建议
> 强调：如何把"提问量下降"这个现象拆成可归因的两部分；如何设计对照组以排除混淆；结论对平台内容运营的含义（UGC 供给一旦塌陷不可逆）

### B. 数据科学家
> **口径**：识别 → 估计 → 推断
> 强调：面板 DiD 的识别假设与检验（平行趋势、安慰剂）；计数因变量用 PPML 而非 log-OLS；cluster 数少时用 wild bootstrap 而非渐近聚类 SE；负权重/异质性处理效应的诊断

### C. 产品 / 策略 / 平台治理
> **口径**：洞察 → 决策
> 强调：反直觉结论（AI 的相对影响没有消退，但流行归因错了）；对 UGC 平台激励设计的含义；"能力门槛"框架可用于预测下一个被替代的领域

**换弹药的核心**：同一个项目，三套要点，每套的第一条都是"对方岗位最关心的那个问题"。不要在投产品岗时把 PPML 写进第一条——那是在说"我只会技术"。

## 五、简历上绝不能写的话（会被当场拆穿）

| ❌ 不要写 | 原因 | ✅ 改成 |
|---|---|---|
| "证明了 AI 导致…" | 观察性数据无法"证明"因果 | "在 XX 识别假设下，估计…" |
| "海量数据 / 大数据" | 253 观测不是海量 | 直接写具体规模 |
| "准确率 95%" | 这是因果推断项目，不是预测 | 报告 DiD 估计与置信区间 |
| "独立完成"却写"团队" | 诚信问题 | 如独立就写"独立研究项目"，面试官会问细节，如实说 |
| 只罗列工具（Python/SQL/Tableau） | 工具不是能力 | 工具放在"用于什么、解决了什么"之后 |

## 六、追问预案（照着说即可）

**Q1：为什么选 Mathematics 做对照？它不也被 AI 影响了吗？**
"正因为它也可能受影响，这个估计才保守。我需要的不是'完全不受影响'的对照，而是'LLM 直接替代性显著更低'的对照——形式证明是 LLM 至今的短板。如果它也被直接替代了，我的 DiD 会趋于零；但我测到 −51.7pp 的差距，说明编程领域承受了显著的额外冲击。"

**Q2：平行趋势满足吗？**
"不满足——这正是我第一轮跑出的结果，伪处理时间安慰剂 p 值 1e-18。我诊断出原因是新技术栈的采用曲线：bun、sveltekit 这些 2022 年后才兴起，天然在上升，会制造虚假的'高语料=跌幅大'梯度。加入领域特定二次趋势后，所有安慰剂检验通过。"

**Q3：样本只有 11 个 tag、8 个站点，够吗？**
"绝对规模确实小，所以我没有依赖渐近推断。cluster 数只有 6–11 时渐近聚类标准误会严重低估，我改用 Rademacher wild cluster bootstrap 重做推断，并且报告的结论方向是横截面一致性——七个独立领域同时触底，这比任何一个系数都难用噪声解释。"

**Q4：pp 口径和 log 口径结论相反，你信哪个？**
"两者都对，分歧来自地板效应。SO 跌了 99%、只剩三千多条时，绝对下降空间被算术压缩，百分点差距必然收窄——这是约束不是行为。要回答'AI 的替代是否在持续'，对数口径更合适，它显示差距从 53.8% 扩大到 91.2%。所以我不会说'AI 的影响在消退'，那是误读。"

**Q5：这有什么商业价值？**
"它纠正了一个正在影响决策的错误叙事。如果平台方以为 UGC 塌了是因为 AI、无法挽回，可能会放弃内容激励；但数据显示后期崩塌里有很大一块是跨领域的普遍性衰亡，那是运营和产品决策能影响的部分。"

**Q6：如果继续做会做什么？**
"三件事：把回答端数据接进来，分离需求塌陷和供给塌陷——后者才是 model collapse 的真正来源；扩大对照站点做正式合成控制；把同样的门槛框架放到中文技术社区检验跨语言稳健性。"
